# Variable Mass System (2D Rocket Simulation)

Лабораторная работа по вычислительному моделированию: программа для расчёта и визуализации плоской баллистической траектории и динамики движения тела переменной массы в 2D-пространстве.

## Общее описание

Приложение моделирует движение ракеты в двумерной плоскости $(x, y)$ на основе **уравнения Мещерского в векторной форме**:

$$m(t) \frac{d\vec{v}}{dt} = \vec{F}_{\text{gravity}} + \vec{F}_{\text{drag}} + \vec{F}_{\text{thrust}}$$

где реактивная тяга $\mathbf{F}_{\text{thrust}} = -\mu \mathbf{u}_{\text{rel}}$ направлена по вектору скорости ракеты (гравитационный разворот / касательная тяга) или под фиксированным углом запуска $\alpha$, а масса убывает линейно по мере сгорания топлива: $m(t) = m_0 - \mu t$.

**Связь с уравнением Циолковского (Частный случай):**
Поскольку ядро реализует общую 2D-динамику Мещерского, классическая формула Циолковского $\Delta v = u_{\text{rel}} \ln(m_0 / m_{\text{dry}})$ получается из модели автоматически как частный предельный случай при подстановке параметров невесомости и вакуума ($g = 0$, $C_d = 0$). Это используется в модульных тестах для верификации точности численного решателя.

**Результат работы:**

* построение 2D-траектории полёта $y(x)$ и графиков зависимости координат, модулей скорости и ускорения, а также массы от времени;
* высокоточное определение отметок ключевых этапов полёта (момент выгорания топлива $t_{\text{burn}}$, точка апогея $v_y = 0$, момент падения на землю $y = 0$) с помощью линейной интерполяции между шагами;
* визуализация векторов скорости $\mathbf{v}$, реактивной тяги $\mathbf{F}_{\text{thrust}}$ и аэродинамического сопротивления $\mathbf{F}_{\text{drag}}$ вдоль траектории;
* интерактивное управление графиками (масштабирование, панорамирование, легенда, подписи осей).

## Входные параметры

### 1. Физические параметры ракеты (Обязательные)

| Параметр | Описание | Ограничения |
| :--- | :--- | :--- |
| `m0` | Стартовая масса ракеты с топливом (кг) | строго положительный (`m0 > mDry`) |
| `mDry` | Сухая масса конструкции ракеты без топлива (кг) | строго положительный (`mDry > 0`) |
| `dmDt` | Массовый расход топлива $\mu = dm/dt$ (кг/с) | строго положительный (`dmDt > 0`) |
| `uRel` | Относительная скорость истечения газов из сопла (м/с) | строго положительный (`uRel > 0`) |
| `launchAngle` | Начальный угол запуска относительно горизонта (градусы) | `0° < launchAngle ≤ 90°` |
| `dt` | Шаг времени дискретизации расчёта (с) | строго положительный (`dt > 0`) |

### 2. Параметры окружающей среды и аэродинамики (Константы / Среда)

Позволяют переключаться между движением в атмосфере, баллистикой в вакууме и невесомостью (для проверки уравнения Циолковского). Сила сопротивления рассчитывается как:

$$\vec{F}_{\text{drag}} = -\frac{1}{2} \rho \|\vec{v}\| C_d A \vec{v}$$

| Параметр | Описание | Значение по умолчанию |
| :--- | :--- | :--- |
| `G` | Ускорение свободного падения (м/с²) | `9.81` (при `0.0` — режим Циолковского) |
| `DragCoefficient` ($C_d$) | Коэффициент лобового сопротивления | `0.45` (при `0.0` — вакуум) |
| `CrossSectionArea` ($A$) | Площадь поперечного сечения ракеты (м²) | `0.5` |
| `AirDensity` ($\rho$) | Плотность атмосферы (кг/м³) | `1.225` |

**Валидация старта (3 уровня защиты):**
При наличии гравитации ($G > 0$) вертикальная составляющая стартовой тяги должна строго превышать вес ракеты, иначе отрыв от стартового стола невозможен:

* **Model:** выбрасывает `ArgumentException`, если $u_{\text{rel}} \cdot \mu \cdot \sin(\alpha) \le m_0 \cdot G$ при $G > 0$.
* **ViewModel:** блокирует `LaunchCommand` (кнопка запуска становится неактивной).
* **View:** отображает предупреждение `"Недостаточная тяга для отрыва от стартового стола"`.

## Архитектура и Вычислительное ядро

Проект построен по шаблону **MVVM** на платформе **.NET 9.0 + Avalonia UI** и разделён на независимые сборки: **Model** (физические расчёты и решатель), **ViewModel** (логика представления, валидация и команды) и **App / View** (графический интерфейс).

**Математическая модель (2D Vector Engine):**
Состояние ракеты в каждый момент времени описывается вектором `[Position(x, y), Velocity(vx, vy), Mass, Time]`. Численное интегрирование системы ОДУ выполняется методом Рунге — Кутты 4-го порядка (**RK4**) в векторной форме.

**Особенности вычислительного ядра (Model):**

1. **Обработка разрывов правой части ОДУ (Адаптивный шаг):** В момент полного выгорания топлива $t_{\text{burn}} = \frac{m_0 - m_{\text{dry}}}{\mu}$ реактивная тяга скачкообразно падает до нуля. Чтобы избежать ошибки аппроксимации на шаге перехода, решатель автоматически дробит шаг интегрирования ровно до границы $t_{\text{burn}}$, а затем продолжает расчёт баллистического участка (свободный полёт).
2. **Точное детектирование событий:** Моменты достижения апогея ($v_y = 0$) и падения ($y \le 0$) определяются линейной интерполяцией между соседними узлами сетки интегрирования.
3. **Верификация по Циолковскому:** В набор модульных тестов (`Model.Tests`) включён эталонный тест: при $G = 0, C_d = 0$ численно полученная конечная скорость $\|\vec{v}(t_{\text{burn}})\|$ сверяется с аналитическим значением $u_{\text{rel}} \ln(m_0 / m_{\text{dry}})$ с точностью до $10^{-6}$.

## Правила работы с Git

(основная музыка данного раздела — «Джентльмены удачи»)

* Основная ветка — `main` (только Император репозитория одобряет через себя коммиты и пуши — иначе четвертуют).
* Рабочая ветка — `development` (основная ветка рабочего продукта нашего творения — кто посмеет критиковать, в темницу).
* Личные ветки участников — `draft-core` (расчётное ядро) и `draft-ui` (интерфейс и графики — кто посмеет сделать шаг влево или шаг вправо в чужую ветку, уволен).
* Коммиты пишутся на английском языке в повелительном наклонении: `feat(core): add 2d meshchersky solver`, `fix(ui): validate fuel mass input` (не знаешь английский? — бан навсегда).
* Перед слиянием в `development` — обязательный Pull Request и одобрение тимлида (Императора репозитория. Бэкдоры и обходные пути или попытка сразу запушить в `development` — ЦРУ, КГБ и Интерпол вас найдут).
* **!!!!!! Запрещено !!!!!!** удалять ветки и склеивать коммиты (squash) при merge — вся история коммитов сохраняется для проверки преподавателем (иначе покарают меня, а заодно и наш Триумвират).
